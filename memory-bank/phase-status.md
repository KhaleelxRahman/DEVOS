### Phase 2D notes

- **preview_url derivation (FIXED, deployed):** `start_preview` now derives the public base URL from the incoming request (`host` header / `request.url.netloc`, `x-forwarded-proto` / `request.url.scheme`) and passes it to `ExecutionService.start_dev_server(public_base_url=...)`. `start_dev_server` builds `execution.preview_url` from that derived base (falling back to `settings.PUBLIC_BACKEND_URL` only when None). This replaces the previous hardcoding to `http://localhost:8000` which was wrong on Render/production. Commit `345cf3e`.
- **preview_token in iframe URL (RECORDED, NOT fixed — flagged for Phase 2G):** The iframe `src` is built as `{preview_url}?preview_token=<devos_token>` (frontend `PreviewPanel.tsx` reads `localStorage.getItem('devos_token')` and appends it). The backend proxy accepts the token as a query param and validates it against the execution owner. This is functional but **is an adversarial-security surface** — a JWT riding in a URL can leak via browser history, server logs, referer headers, and third-party iframe embeds. **Not fixing now; explicitly flagged for Phase 2G's adversarial security pass.**

### Phase 2E notes

- **Real defects found and fixed this phase (commit `074dac0`, deployed):**
  1. *State-management defect* — retry/cancel did not correctly reject non-retryable live states in a race (an execution could be acted on while QUEUED/RUNNING). Fixed so the terminal-state check happens against the committed row state.
  2. *Database/migration defect* — `c520db81c7c6` performed unconditional `op.add_column` for `parent_execution_id` / `retry_count`, but the base executions migration (`3e7e5a9c4f1b`) already creates `parent_execution_id` and its index, producing `duplicate column name: parent_execution_id`. It now follows the repo's existing inspector-guard convention used by `3e7e5a9c4f1b` and `a4b7cd5e6f80`.
- **Retry semantics (final, matches the implementation):** `retry_count` on the **original** = number of retries performed (0, 1, 2…); `retry_count` on the **child** = its attempt number (1, 2, 3…); `parent_execution_id` on the child links to the original's `execution_id`.
- **Local `alembic current` observation (not a defect):** the local dev SQLite file reports `9c8d7e6f5a4b`, i.e. behind the head `c520db81c7c6`. This is a pre-existing local dev artifact; it does not affect the suite (the test harness builds its own schema — 129/129 passed) nor production, where `parent_execution_id` / `retry_count` / `completed_at` persistence is proven directly by the live production API responses above.
- **Residual UX gap (unchanged, honest):** the deployed Workspace terminal UI still exposes **no** Stop/Cancel and **no** Retry control (`02-frontend/src/components/workspace/TerminalPanel.tsx` has only New terminal / Copy / Run command / Clear). Phase 2E cancellation + retry are therefore **API-verified in production (real HTTP 200/422/403 + real state transitions), not browser-UI-verified** — there is no supported production UI control to click. This is a UX/UI gap to be closed by the later UX phase, not a backend defect.
- **No orphan policy:** stop / cancel / session-end / timeout all kill the real process and clear the in-memory registries; a subsequent start obtains a fresh port, proving the previous bind was released.
